# 01 要件

## 背景

- 依頼主：ファストフード店（フランチャイズ加盟店）のオーナー。開発者の友人
- 開発者は同じ店で働いた経験があり、現場のシフトの中身を理解している
- 今は店長が紙（Excel）で1週間分のシフト表を作っている。希望の集約と穴埋めに時間がかかる

## 今のシフト表の形式（再現する）

紙の週間シフト表を元に、アプリの出力はこの形にそろえる。

実物の写真（2026-11-01 にオーナーから受領。実名・店名が写っているためリポジトリには置かない）で確認した構造。

- A4縦1枚に月〜日を**7つのブロック**として縦に並べる。ブロックの左端に「◯月◯日」＋曜日の2段。土曜は青字、日曜は赤字
- 最上部に年（「2026年」）と、中央に「＜店名＞シフト表」の見出し
- **時刻の見出し行は日ブロックごとに繰り返す**（1枚の通し軸ではない）
- 横軸は **8 → 24**（＝ 480分〜1440分、16列）。1時間ごとに数字を振る。
  ※実物の紙は 7:00〜翌3:00 だが、使う範囲に合わせて 8:00〜24:00 に詰めた（2026-11-08）
- 1人1本の色付きバー。勤務時間の範囲を塗って中央に名前。色は人ごとに固定（淡いパステル）
- 朝の人が上から並び、時間が重ならない夕方〜夜の人は同じ行の右側に入る（行を詰める）
- **1日ブロックの行数は固定**。実物は12行前後で、空いた行は罫線だけが残る。月曜は6本程度、土日は12本前後まで埋まる
- 右端に「備考」列（日ブロックごとに1セル。例：「シェイク分解」「〇〇半休」。色文字で書き分けている）
- 下に注意書き「※シフト希望は毎週木曜日〆切です。原則雇用時通りの提出を心掛けてください。」
- ホール／キッチンの区別は表に出していない（店長の頭の中にある → スキルカードで管理する）

**実装メモ**
- デモの `weekTable()` はレーンを6行に揃えているが、実物は12行前後。**レーン数の既定を見直す**こと
- 「30分刻みの罫線」と「30分単位の勤務はいない」（`06` #2）は両立する。*表示グリッドは30分、勤務は1時間* の可能性が高いが、バーが30分位置から始まっている行があるため要確認
- テンプレートシート複製方式（`05` Phase 5）をとるなら、**写真ではなく元の Excel ファイル**が必要（列幅・行高・フォント・印刷設定は画像から復元できない）

## 業務フロー（2段階）

この店は **月の暫定 → 週の確認** の2段階で希望を集めている（`06` #10）。

### ① 月の暫定（月のはじめ）

1. 店長が店長画面の「スキル」タブ →「対象の月と週」で **次の月を開く**。
   月の暫定（受付中）と、その月に含まれる週（準備中）がまとめて作られる
2. スタッフは **曜日でまとめて**「だいたいこの時間」を決め、違う日だけ **カレンダーで日ごとに**直す。
   「いつも通りで提出」の1タップでも終わる（「毎週月曜17時、でも22日だけ休み」ができる）
3. この時点では確定ではなく、シフト作成の下敷き

### ② 週の確認（毎週）

1. **募集開始（月曜）**：店長が対象週を［受付中にする］で開ける。LINEで「来週分の希望を受付中」と知らせる。
   画面には **月の暫定がそのまま入っている**ので、変わらなければ1タップで終わる
2. **提出**：スタッフがLINEのメニュー → LIFF画面。暫定の内容が表示されていて「このままで提出」1タップ、または「この週は変える」で日ごとに入力
3. **受付確認**：提出直後に画面で完了表示。LINEのトークにも内容が届く
4. **修正**：〆切まで何度でも修正可
5. **リマインド（水曜夜）**：未提出の人にだけ通知
6. **〆切（木曜23:59）**：入力を締める
7. **作成**：店長が自動作成 → チェック（ルール違反の警告）を見ながら手直し
8. **確定・配信**：確定するとシフト表（紙形式）を出力し、スタッフに知らせる

## 機能（優先順位）

### MVP（友人の店で使い始めるのに必要）

- S1 本人の紐付け（初回だけ招待コード入力でLINEアカウントとスタッフを結びつける）
- S2 「いつもの勤務」の表示と「いつも通りで提出」
- S3 曜日ごとの入力・修正、「この内容をいつもの勤務にする」
- S4 受付完了表示と、LINEトークへの受付メッセージ（送信数を使わない「応答」で返す。方法は `03` 参照）
- M1 提出状況一覧（誰が未提出か）
- M2 スキルカード編集（ポジション別レベル0〜3、責任者、締め、週の上限時間、NG相手、いつもの勤務）
- M3 店のルールのON/OFF（5種類。`04` 参照）
- M4 必要人数の設定（時間帯×ホール/キッチン、土日ピークの加算）
- M5 叩き台の自動作成
- M6 週間シフト表（紙形式）表示、チェック一覧、手直し（外す・時間を変える・追加する）
- M7 確定して、紙形式のシフト表をスプレッドシートの1シートに出力（印刷・PDFは Sheets から）

### 次の段階

- N1 募集開始・リマインドの自動通知（送信数の上限に注意）
- N2 確定シフトをスタッフ本人に見せる（LIFFで「自分の来週のシフト」）
- N3 開店準備・締めの時間帯を必要人数に入れる（表の軸は最初から 7:00〜翌3:00）
- N4 祝日を土日扱いにする

### やらない（今は）

- **30分単位の勤務**（`06` #2 で該当者なしと確定。`grid_min` は 60 固定）
- **中抜け・1日2回勤務**（`06` #9 で該当なしと確定。1人1日1枠）
- 急な欠勤・交代の受付（今のやり方を聞いてから決める）
- 勤怠・給与計算との連携（`06` #18 で本部にシステムなしと確認。二重入力の心配はない）
- 複数店舗対応

## 成功の目安

- スタッフの提出がほぼ全員「いつも通りで提出」の1タップで終わる
- 店長のシフト作成時間が今より明らかに短くなる（今の時間を店長に聞いて記録しておく）
- 店長が「いつもの表と同じだ」と感じる出力になっている
