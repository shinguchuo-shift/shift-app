# 02 データ設計（Google スプレッドシート）

1つのスプレッドシートに以下のシート（タブ）を置く。1行目は列名。GAS は列名で読み書きする。

**タブ名も列の見出しも日本語**（店長が直接見て直せることを優先）。
コードの中では短い英語のキー（`staff_id` など）を使い、その対応は **`gas/Schema.js`** が持っている。
列を増やす・名前を変えるときは Schema.js だけ直せばよい。以下の表の見出しは、左が日本語（シート）、右がコードのキー。

| コードのキー | タブ名 |
|---|---|
| Settings | 設定 |
| Staff | スタッフ |
| UsualPattern | いつもの勤務 |
| Periods | 対象週 |
| Submissions | 提出 |
| Requests | 希望 |
| Demand | 必要人数 |
| Rules | ルール |
| Shifts | シフト |
| DayNotes | 備考 |
| Log | ログ |

**見出しの行（1行目）は書き換えないこと。** 書き換えると GAS が列を見つけられなくなる。

**セルの値も日本語**。`hall` → ホール、`manager` → 店長 のような読み替えは `Schema.js` の `VALUE_MAPS` が持つ。
真偽の列（在籍・責任者・締め作業・使う）はチェックボックス。
数の単位・形を変える列は `UNIT_COLUMNS`：
**週の上限**はコードが分・シートは時間、**開始／終了**はコードが分・シートは `10:00` の形。
`25:00` のように24時を超える書き方もできる（翌1:00 の意味）。
**ポジションシートは廃止**（担当業務の4分類に置き換わった）。
残すIDは**スタッフID（s01）と期間ID（2026-11-02）だけ**。これは行を見分けるための値なので日本語にしない。
時刻は「営業日の0:00からの分」（整数）。例：10:00 = 600、24:00 = 1440。曜日は 0=月 … 6=日。

## Settings（店の設定）

| key | 例 | 説明 |
|---|---|---|
| store_name | 〇〇店 | シフト表の見出し |
| open_min / close_min | 600 / 1440 | 営業時間 |
| grid_min | 60 | 時間の刻み。**60 固定**（`06` #2 で30分単位の人はいないと確定）。30分対応は「やらない」 |
| sheet_axis_start_min / end_min | 420 / 1620 | シフト表の横軸（7:00〜翌3:00）。`06` #1 で紙のまま維持と確定。営業時間（open/close）とは別物で、軸だけが広い |
| sheet_lanes | 12 | シフト表の1日あたりの行数。実物の紙が12行前後。超えた日は警告を出す |
| deadline_dow / deadline_time | 3 / 23:59 | 〆切の**既定値**（3=木）。実際の判定は Periods.deadline_at を唯一の真実とする |
| peak_ranges | 660-840,1020-1200 | ピーク帯（11〜14時、17〜20時） |
| weekend_peak_boost | 1 | 土日ピークの加算人数 |
| footer_note | ※シフト希望は毎週木曜日〆切です。… | シフト表の注意書き |
| min_shift_min / max_shift_min | 180 / 480 | 自動作成の1回の勤務の長さ |

秘密情報（チャネルアクセストークン、LIFF のチャネルID等）は **ここに置かず** スクリプトプロパティへ。

## Staff（スタッフとスキルカード）

| 列 | 型 | 例 | 説明 |
|---|---|---|---|
| staff_id | 文字 | s01 | 変えない |
| name | 文字 | 佐藤 | 表に出す名前 |
| type | 文字 | 主婦 / 学生 / フリーター | 表示用 |
| role | 文字 | staff / manager | manager は店長画面を使える |
| active | 真偽 | TRUE | **退職者は FALSE にして、行は消さない**。消すと過去のシフトが誰のものか分からなくなる |
| line_user_id | 文字 | U1234… | 紐付け後に自動で入る |
| invite_code | 文字 | K7M2QX94 | 初回紐付け用。**8桁以上の英数**（紛らわしい `0/O`・`1/I/l` を除く）。紐付け後は空にする。4桁だと総当たりで他人になりすませる |
| invite_expires_at | 日時 | | 招待コードの失効日時。過ぎたら `link` を拒否 |
| weekly_cap_min | 数値 | 1500 | 週の上限。**コードは分、シートには時間で表示**（25） |
| leader | 真偽 | TRUE | 時間帯責任者ができる |
| closer | 真偽 | FALSE | 締め作業ができる |
| duty | 文字 | hall / kitchen / both / trainee | 担当業務。シートでは ホール / キッチン / 両方 / 研修中 |
| ng_staff_ids | 文字 | s04,s11 | 組ませない相手（カンマ区切り、両方向に入れる） |
| color_hue | 数値 | 137 | シフト表のバーの色（0〜359） |
| memo | 文字 | | 店長メモ |

**担当業務（duty）が、その人をどこに入れられるかを決める**（`06` #3・#4 で確定）。

| duty | 入れる側 | 備考 |
|---|---|---|
| hall（ホール） | ホールのみ | |
| kitchen（キッチン） | キッチンのみ | |
| both（両方） | どちらでも | |
| trainee（研修中） | どちらでも | **1人きりにしない**（`rookie` ルール） |

ポジション別レベル0〜3は廃止した。「教えられる人」の判定は「研修中でない人」で代用している。

**区分（type）は 社員 / 主婦 / 大学生 / 高校生。**
**高校生は22時以降に働けない**（労働基準法）。`Schema.js` の `TYPE_END_LIMIT` が上限を持ち、
自動作成・スタッフの入力・チェックの3か所で止める。

`ng_staff_ids` は両方向に入れるのが建前だが、**読み出しは OR 判定**（どちらか片方に入っていれば NG とみなす）なので、店長がシートを直接いじって片方だけ入れても機能する。

### 人の入れ替え（スプレッドシートの「シフトアプリ」メニュー）

手でセルをいじるとスタッフIDの重複や招待コードの付け忘れが起きるので、メニューから行う。

| メニュー | すること |
|---|---|
| スタッフを追加 | 次の `staff_id` を振り、招待コードを発行して1行足す |
| 招待コードを発行し直す | コードを作り直し、**紐付けも解除**する（機種変・コードを忘れた・漏れた） |
| 退職にする | `active` を FALSE に。紐付けと招待コードを消す。**行は残す** |
| 復帰させる | `active` を TRUE に戻し、新しい招待コードを発行 |
| 招待コードの一覧を出す | まだ紐付けていない人のコードをまとめて表示（配るとき用） |
| 配布用の紙を作る | 1人ずつ切り取れる紙（名前・コード・リンク）を「招待コード配布」シートに出す |

### プルダウン

店長が手で触る列は**プルダウン**にしてあり、一覧にない言葉は入れられない（`Schema.js` の `dropdownsOf`）。

| シート | 列 | 選べるもの |
|---|---|---|
| スタッフ | 区分 | 社員 / 主婦 / 大学生 / 高校生 |
| スタッフ | 権限 | スタッフ / 店長 |
| スタッフ | 担当業務 | ホール / キッチン / 両方 / 研修中 |
| 期間 | 種類 | 月の暫定 / 週の確認 |
| 期間 | 状態 | 準備中 / 受付中 / 締切後 / 確定済み |
| 必要人数 | 平日・土日 | 平日 / 土日 |
| ルール | 強さ | 必須 / 注意 |

シートを作るとき（`writeTable`）とスタッフを足すときに自動で付く。
既存のシートに後から付けるときはメニューの【入力のプルダウンを整える】。

**招待コードはグループLINEに貼らない。** コードは本人になりすませる鍵なので、
他の人に見えると先に使われる。口頭・個別LINE・紙（切り取って手渡し）で渡す。
全員に一度に配る必要はなく、出勤したときに1人ずつ渡せばよい。

人数に上限はない。行を足せばいくらでも増やせる（60人でも問題ない）。

`color_hue` が色の唯一の真実。`Setup.js` のサンプル投入時に `(index * 137) % 360` を書き込む。`staff_id` は文字列なので、デモのように ID から色を計算してはいけない。

## UsualPattern（いつもの勤務）

| staff_id | dow | start_min | end_min |
|---|---|---|---|
| s01 | 0 | 600 | 900 |

行がない曜日は「休み」。**1人1曜日1行で確定**（`06` #9 で中抜けなしと確認。将来対応のための配列化・`slot_no` 列は入れない）。

「いつもの勤務が未登録の人」と「全曜日休みの人」はこの表では区別できない。MVPでは「1行もなければ未登録」として扱う（実害が出たら Staff に `usual_set` 列を足す）。

## Periods（募集期間＝対象週）

| period_id | start_date | end_date | deadline_at | status | revision |
|---|---|---|---|---|---|
| 2026-11-02 | 2026-11-02 | 2026-11-08 | 2026-10-29 23:59 | open | 1 |

status：`draft`（準備中）→ `open`（受付中）→ `closed`（〆切後）→ `published`（確定・配信済み）。

`deadline_at` が **〆切判定の唯一の真実**。Settings の `deadline_dow` / `deadline_time` は `mgr.openPeriod` が初期値を計算するためだけに使う。両方を見て判定しないこと。

`revision` は Shifts 保存の衝突検出用（下記 Shifts 参照）。保存のたびに1増やす。

## Requests（提出された希望）

| period_id | staff_id | date | start_min | end_min | rev | active |
|---|---|---|---|---|---|---|

出られる日だけ行がある。1人1日1行（中抜けなし）。
提出したが全部休みの人は Submissions にだけ行がある。

**修正時に行を削除してはいけない。** 削除は行番号で行うため、〆切直前に複数人が同時に提出すると、他人の行を消してしまう。代わりに：

- 提出のたびに `rev` を1つ増やして**追記だけ**する（`appendRow` 1回で済む）
- 古い行は `active=FALSE` にする、または**読み出し側が staff ごとの最大 rev だけを採る**
- 書き込み系の処理は `LockService.getScriptLock().waitLock(30000)` で囲む（`getDocumentLock()` は Web アプリから呼ぶと使えない）
- 読み取り専用の処理（`me` / `mgr.load`）には**ロックをかけない**。かけると〆切直前に全員が直列化して詰まる

行は period ごとに溜まっていく（20人×7日＝週140行、1年で約7,300行）。`readTable` は **period_id で絞ってから**返すこと。溜まりすぎたら `Archive_Requests` へ退避する関数を `Setup.js` に用意する。

## Demand（必要人数）

| day_type | start_min | hall | kitchen |
|---|---|---|---|
| weekday | 600 | 2 | 2 |
| weekend | 600 | 2 | 2 |

day_type は weekday / weekend（将来 holiday）。start_min は grid_min ごとの行（＝60分ごと、営業時間 600〜1380 の14行）。
土日ピークの加算は Settings の weekend_peak_boost で計算時に足す（Demand には素の値を置く）。

実際の値は `06` #6 で店長に聞く。それまではデモの値（ホール/キッチンとも `2,3,3,3,2,2,2,3,3,3,2,2,1,1`）を仮置きする。

## Rules（店のルール）

| rule_key | enabled | level | label |
|---|---|---|---|
| leader | TRUE | error | 営業中は毎時間、時間帯責任者を1人以上 |
| peak3 | TRUE | error | ピーク帯はホール・キッチンそれぞれ研修中でない人を1人以上 |
| close | TRUE | error | 閉店時は締め作業ができる人を1人以上 |
| ng | TRUE | error | NG組み合わせは同じ時間に入れない |
| rookie | TRUE | warn | 研修中の人を1人きりにしない |

`level` は `error`（絶対）か `warn`（できれば）。`06` #5 で店長に聞いた答えをここに入れる。
`checks()` はこの列を読む。コードに error/warn を直書きしない。

## Shifts（作成したシフト）

| period_id | date | staff_id | side | start_min | end_min | source | updated_at |
|---|---|---|---|---|---|---|---|

side：hall / kitchen。source：auto（自動）/ manual（手直し）。1人1日1行（中抜けなし）。
確定前は何度でも上書き。確定時に Periods.status を published にする。

**上書きの衝突に備える。** 店長はスマホとPCの両方で開く（`01`）ので、2端末で開いたまま保存すると後勝ちで作業が消える。Periods に `revision` 列を足し、`mgr.saveShifts` は受け取った revision が現在値と違えば保存せず `{ok:false, error:"conflict"}` を返す。画面には「別の端末で変更されています。読み込み直してください」と出す。

## Log

| at | type | staff_id | detail |

送信したLINEメッセージ（送信数の管理）、エラー、確定操作を残す。
**認証の失敗と権限拒否も必ず残す**（招待コードの総当たりに気づくため）。

## シフト表_YYYY-MM-DD（出力用）

確定時に GAS が作る、紙と同じ見た目のシート。データの元にはしない（見る・印刷する専用）。

**「_シフト表テンプレート」を複製して作る。** Sheets API には用紙サイズ・向き・余白・「1ページに収める」を設定する手段がない（`SheetProperties` にそのフィールドが存在しない）ので、コードから A4縦を指定することはできない。印刷設定を手で1回だけ済ませたテンプレートシートを置き、`copyTo()` で複製して中身だけ書き換える。シートの複製は印刷設定を引き継ぐ。

店から元の Excel をもらえたら、**それをそのままテンプレートにする**のが最短（列幅・行高・フォント・印刷設定がすべて正解の状態で手に入る）。名前バーと備考だけ消して枠を残す。
